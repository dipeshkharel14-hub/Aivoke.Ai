# Aivoke, Phase 1: setup, design system, database

## Files created
- `.env.example`, `.gitignore` (blocks `.env*`), `next.config.ts` (security headers + CSP baseline)
- `app/globals.css` (tokens, light + navy dark, focus, reduced motion), `app/layout.tsx`, `app/page.tsx`, `app/design/page.tsx` (noindex design-system page)
- `components/` theme-toggle, site-header, site-footer (only place the support email appears, read from `SUPPORT_EMAIL`)
- `lib/env.ts` (zod-validated, server-only), `lib/site.ts`, `lib/utils.ts`, `lib/supabase/{client,server,admin}.ts`
- `supabase/migrations/0001..0007` and `supabase/seed.sql` (123 tools, 18 categories, generated by `scripts/generate-seed.mjs`)

## Set up the app
```bash
npx create-next-app@latest aivoke --typescript --tailwind --eslint --app --no-src-dir --import-alias "@/*"
# copy this folder's files over the generated project (overwrite app/layout.tsx, app/page.tsx, app/globals.css)
cd aivoke
npm i @supabase/supabase-js @supabase/ssr zod server-only framer-motion @google/genai @upstash/redis @upstash/ratelimit resend
cp .env.example .env.local   # then fill in values
npm run dev
```
`globals.css` uses Tailwind v4 syntax (`@import "tailwindcss"`, `@theme`). If your install gives Tailwind v3, tell me and I will convert it.

## Set up the database
1. Create a Supabase project. In the SQL editor run `0001` to `0007` in order, then `seed.sql`.
   (CLI alternative: `supabase link`, `supabase db push`; `supabase db reset` also runs `supabase/seed.sql`.)
2. Copy URL, anon/publishable key and service-role key into `.env.local`.

## How to test
Run in the SQL editor:
```sql
select count(*) from public.tools;        -- 123
select count(*) from public.categories;   -- 18
select relname from pg_class where relnamespace = 'public'::regnamespace and relkind = 'r' and not relrowsecurity;  -- 0 rows
select count(*) from public.tools where embedding is not null;  -- 0 until phase 4
```
Client-role checks (replace the uuid with a user from Authentication > Users after one signup):
```sql
select set_config('request.jwt.claims', '{"sub":"<USER-UUID>","role":"authenticated"}', true);
set local role authenticated;
update public.profiles set points = 999 where id = '<USER-UUID>';   -- must fail: permission denied for column points
insert into public.points_ledger (user_id, delta, reason, idempotency_key) values ('<USER-UUID>', 5, 'x', 'x');  -- must fail
select embedding from public.tools limit 1;                          -- must fail: permission denied
```
In the browser: `npm run dev`, open `/design`, toggle dark mode, tab through the page (focus ring visible), and check the footer shows only `info@khareldipesh.com.np`.

## What you must configure manually
- Supabase project and keys; Upstash, Resend, Turnstile, Gemini keys can stay placeholders until their phases.
- `GEMINI_*_MODEL` names (I did not hardcode any model). Embedding dimension is fixed at 768 in the schema; if your embedding model outputs another size, change `vector(768)` in `0001` and `0004` before running them.

## Decisions and assumptions to confirm
- Level thresholds (Builder 100, Pro 500, Master 2000 lifetime points) and reward costs in `0007` are placeholders.
- `tagline` is derived from the first sentence of each tool's existing description in index.html; edit in admin later.
- Reviews are written by a server route (spam checks, Turnstile), not directly by clients. Avatars are uploaded through a server route that verifies file type; clients can only read and delete their own avatar folder.
- Days for rewards use UTC.
